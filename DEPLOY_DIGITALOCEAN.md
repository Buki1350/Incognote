# Incognote - DigitalOcean deployment audit

## 1. Project analysis

- Backend: Rust 2021, Axum, Tokio, sqlx, PostgreSQL, JWT, Argon2, reqwest, lettre.
- Frontend: static HTML, CSS and vanilla JavaScript served by Nginx.
- Database: PostgreSQL. Tables are created at service startup by `auth-service/src/db.rs` and `notes-service/src/db.rs`; `database/schema.sql` is a reference schema.
- Services: `auth-service` listens on 3001, `notes-service` listens on 3002, Nginx exposes the frontend on 80 and proxies `/api/auth/*` and `/api/notes/*`.
- External dependencies: PostgreSQL, optional SMTP server, optional `https://ipapi.co` geolocation API.
- Runtime secrets/config: provided through `.env` and consumed by `docker-compose.yml`.

## 2. Minimal DigitalOcean architecture

Use one DigitalOcean Droplet with Docker and Docker Compose.

- Droplet: one VM is enough because the project can run app and database containers on the same host.
- Docker Compose: keeps PostgreSQL and the combined app image together without adding managed services.
- PostgreSQL container with named volume: simplest persistent database for this scope.
- No App Platform: App Platform would still need a persistent PostgreSQL service; that adds complexity and cost.
- No Managed Database: not required for this deployment goal.

Recommended starting size: Basic Droplet 1 GiB RAM / 1 vCPU. If builds fail due to memory, resize to 2 GiB RAM or build locally and deploy the image.

## 3. Required changes

- `Dockerfile`: use `nginx:1.27-bookworm` instead of Alpine so Debian-built Rust binaries run on glibc; keep a single app image containing Nginx, auth and notes services.
- `docker-entrypoint.sh`: keep ports isolated and allow `AUTH_SERVICE_URL` override while defaulting to local auth service.
- `.dockerignore`: exclude real `.env` files from Docker build context.
- `.gitignore`: keep real env files ignored, but allow `.env.production.example` to be committed.
- `docker-compose.yml`: new production compose file for app + PostgreSQL.
- `.env.production.example`: new complete environment template.
- `DEPLOY_DIGITALOCEAN.md`: this deployment audit and runbook.

## 6. DigitalOcean deployment steps

1. Create or log in to a DigitalOcean account at `https://cloud.digitalocean.com`.
2. Click `Create` -> `Droplets`.
3. Choose image: `Marketplace` -> `Docker`.
4. Choose region close to users, for example Frankfurt or Amsterdam.
5. Choose size: `Basic`, `Regular`, `1 GiB / 1 vCPU`. Use `2 GiB` if you want safer on-server Rust builds.
6. Authentication: choose SSH key if available. If not, choose password and save it.
7. Firewall: allow inbound TCP `22`, `80`, and optionally `443`. Do not expose `3001`, `3002`, or `5432`.
8. Create the Droplet and copy its public IPv4 address.
9. SSH into the Droplet: `ssh root@YOUR_DROPLET_IP`.
10. Install Git if missing: `apt update && apt install -y git`.
11. Clone the project: `git clone YOUR_REPOSITORY_URL incognote && cd incognote`.
12. Create env file: `cp .env.production.example .env`.
13. Edit env file: `nano .env`. Replace passwords/secrets and set `APP_BASE_URL=http://YOUR_DROPLET_IP`.
14. Start deployment: `docker compose up -d --build`.
15. Check status: `docker compose ps`.
16. Check logs if needed: `docker compose logs -f app`.
17. Open `http://YOUR_DROPLET_IP` in a browser.

Domain is optional. If you have one, create an `A` DNS record pointing to the Droplet IP and set `APP_BASE_URL=http://your-domain.com`. HTTPS is not configured by this minimal setup; add a reverse proxy with TLS later if needed.

## 7. Troubleshooting

- Build fails or the Droplet becomes slow: resize to 2 GiB RAM or build on another machine.
- App opens but login fails: run `docker compose logs app` and check `JWT_SECRET`, `NOTE_ENCRYPTION_KEY`, `DATABASE_URL`.
- Database does not start: run `docker compose logs postgres`; verify `POSTGRES_PASSWORD` is set.
- Public URL does not open: verify Droplet firewall allows port 80 and `docker compose ps` shows the app container running.
- Registration/login rejects email provider: add the email domain to `TRUSTED_EMAIL_DOMAINS`.
- Password reset email fails: configure `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, and `MAIL_FROM`.

## 8. Final result

- DigitalOcean services needed: 1 Droplet.
- Estimated monthly cost: about 6 USD/month for the recommended 1 GiB Basic Droplet, or about 12 USD/month for 2 GiB.
- URL after deployment: `http://YOUR_DROPLET_IP`, or `http://your-domain.com` if a domain is attached.
- Working after deployment: frontend, auth API, notes API, PostgreSQL persistence, admin bootstrap, registration/login, notes CRUD, sharing, friends, messages, admin views.
- Verified locally with Docker Compose on port 18080: image build, PostgreSQL health, frontend HTTP 200, auth health, notes health, admin login, note create/list, user registration/login, friend invite/accept, note sharing, message send/list.
